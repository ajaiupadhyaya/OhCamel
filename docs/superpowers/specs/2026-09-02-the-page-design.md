# OhCamel — the page

*Design, 2026-09-02. This succeeds the dashboard described in the essay at the head of `lib/dashboard_html.ml`. That essay is kept — archived verbatim at the head of `web/index.html`, where the successor is — and its three moves are kept with it. What follows is what the page becomes when the graph itself is drawn on it.*

*How it was made: five readers mapped the subsystems a page would draw on; three designers proposed from three angles (an argument, a console, the graph); three judges scored them (the graph won two lenses, the argument won the interviewer's); one synthesis; one completeness critic. Four choices were the owner's and were made on 2026-09-02: one document at `/` plus `/ops`; `/ops` and `/api/ops` public on the demo host with a CORS header on the demo engine's JSON routes; the GARCH study computed by this process on a second domain; an observer on the attribution node. The critic's corrections are folded in where they land and marked* amended.

---

## Problem

The dashboard at `/` shows the book. Three columns in dependency order, changed values underlined, numbers that lose their authority when the feed does. It is a good page and it is honest, and it shows almost nothing of what the project is.

It does not show the graph. The thesis — that risk is a dependency graph and a tick recomputes exactly what is downstream of it — is asserted by the column order and inferred by the client, which diffs successive snapshots and underlines what moved. The engine knows precisely which node bodies ran; the page guesses from the values. That is one level removed from the thing the project is about, and a reader at Jane Street will notice the gap even if they cannot name it.

It does not show the reports. The coverage battery with its four tests, the same battery over the 2008, 2020 and 2022 windows, the Euler decomposition beyond a percentage column, the options walk with its second clock, the GARCH study that keeps GARCH out, the scaling table, the scenario suite — every one of these exists only as the terminal output of `ohcamel <mode>` and as README prose. The README quotes them as code blocks. A recruiter reads code blocks as claims, and the deployed host, which could reproduce most of them on demand, reproduces none.

It does not show the process. The owner runs two hosts and learns whether the live engine is up, which build it is, whether the stream is parked or dead, and whether the Alpaca socket has reconnected, by opening a terminal on the droplet. `Server.frames_sent` and `subscriber_count` exist and nothing calls them. The live host's `/api/snapshot` says alerts are `enabled: false` because `run_live` never passes `?alerts` to `Server.create`, so whatever the switch's state is, the wire cannot say it. *Amended:* today the live host runs the committed example book, whose alerts are off and whose kill switch is disabled, so the wire happens to be right for the wrong reason; the fix is still made, and the page reports what the wire then says rather than assuming an armed switch that is not there. Nothing records a start time. The image has no git sha, because `.git/` is dockerignored and no build argument carries one, so the smoke suite cannot tell whether `up -d` replaced the container or kept the old one.

Three purposes, then, and they pull in different directions. Proof wants the argument first and nothing above it. Monitoring wants ages in seconds above the fold and works on a phone at two in the morning. Reporting wants the tables the CLI prints, on the web, with provenance. A console above the fold tells an interviewer nothing about the engine; an essay tells the owner nothing about the host. This design is the resolution of that tension, not a compromise between the three.

## Goal

One document at `/`, served identically on both hosts, whose spine is the Incremental graph as it is coded — every named node, every declared edge, taken from Incremental's own node table — with each frame's recomputation set lit on it, the existing ledger read against it, and the CLI's reports continuing below it under the README's own headings, each opening with the fragment of the drawing it interrogates and each saying, in one of three fixed ways, where its numbers came from. And one small, plain page at `/ops` for the owner: both hosts, ages in seconds, the smoke suite's two load-bearing assertions running continuously in the browser, the build that is running and how long it has been up.

The interviewer with eight minutes gets the graph lit by real data in the first screen and the battery two scrolls down. The owner with a phone gets `/ops`. The reports are the CLI's records, encoded, not retyped.

## Non-goals

- **No mutating route.** The scenario suite's "run it again" is a GET that forks and discards, exactly as `/api/stress` does today. Nothing on either page arms, trips, resets, submits, restarts or persists. The kill switch stays a bool wired to nothing and the page draws that fact.
- **No persistence.** Every report is computed into process memory at startup and is gone at restart. The history ring stays 500 points and the page keeps saying so. There is consequently no uptime percentage and no record of the last smoke run; the page says both.
- **No external asset.** No CDN, no web font, no charting library, no framework. Each page remains one self-contained HTML string in the binary, built from `web/` at compile time. Every chart is inline SVG drawn by hand in the idiom the sparklines already use.
- **No weakening of the live host's gate.** The live host stays behind site-wide basic-auth with no matcher exemptions. No `/api/up`, no Caddy CORS on the live host, no proxying of live data through the demo engine. `/api/health` names every symbol in the live book; the day `book.sexp` on the droplet is edited it names the owner's positions, so it is never un-gated, and a counts-only sibling that could be un-gated is not built because the owner can open the other tab.
- **No live options Greeks and no invented vol surface on either host.** The options figure is a one-name NVDA graph with the CLI's synthetic smile, labelled SYNTHETIC in every line it appears in; the ledger on the live host prints "options DISABLED — no options-chain source" as a line rather than hiding the rows.
- **No number this process did not produce styled as if it had.** The M2 Pro microseconds, the test count and the coverage figure are quoted, dated, and set in a lighter ink. `bench/` is not in the image by design and stays out of `lib/` (invariant 2).
- **No second implementation of anything the engine computes.** The client derives closures from the served topology and tallies from served frames; it never recomputes risk. The CLI modes become printers over the same records the routes encode, so the web and the terminal cannot drift.
- **Not a third page.** Reports live on `/`. The reasons are in the next section.

## The shape: one document, and one small page for the phone

The three proposals this design comes from split the same material three ways: an argument in nine sections, a console with reports in closed panels, and a graph with the reports on a second page and the operations on a third. The judges scored the graph highest and then said, in three different voices, that the reports should not be a click away, that a console should not be above the fold, and that the graph page does not work on a phone.

So: `/` is one document. Its first screen is the drawn graph with the current frame lit on it, its second is the ledger the owner already watches, and the argument continues below in the README's order. Nothing is behind a click. `/ops` is a second page because a phone at two in the morning needs two ages in seconds and a flat line that means "dead", and because the two-host view has to live on the live origin, which the owner opens with the password. It is deliberately plain: key/value rows in the ledger's own style, two strips, and a paragraph on what it cannot see. It shares one header, authored once in `web/`, with `/`.

The `/` header carries what the owner needs on a laptop in two seconds: last print age, last frame age, alerts state, named nodes recomputed this frame. The process-wide counter, GC, pid and the rest go to the footer and to `/ops`, so the header does not crowd on a narrow screen. Below 700 px the header stops being sticky and the graph section shows the lit node names as a list instead of the SVG, with a line saying the drawing reads best on a laptop.

## Information architecture

### `/` — the document

Source: the SSE frame; mode from `/api/ops`, fetched once at load.

**Banners.** The halt banner and the stale banner, exactly as today. On the live host outside hours the stale banner stays — the numbers are from old marks — and the explanation ("market closed") is not the engine's to give; it appears nowhere, because a holiday calendar the page does not have is not knowledge.

**Figure 1 — the graph.** Full width, inline SVG, about 360 px tall on a six-name book, scrolling horizontally inside its own container below 1100 px. Ranks are columns, assigned by longest path from the input cells in `lib/graph.ml` and served on `/api/graph`; the client never lays anything out. Column heads in the `.lbl` style: `inputs`, `exposure`, `aggregates`, `estimators`, `attribution`, `limits`, `breaches`, and, after a hairline gap, `observers — outside the graph`. Nodes are typographic: the `Node_name` string in monospace with a thin rule beneath, no boxes. Observed nodes carry a small filled dot at their right edge (27 on the demo book). Edges are 0.75 px hairlines in `--rule`, cubic between columns. Input cells are 8 px hollow squares.

Under the singleton nodes, a value in the node's own unit, from the frame's `by_node`: gross, net, equity in dollars; drawdown as a percentage; the four estimators as fractions of gross, `var_notional` and `es_notional` in dollars; beta to three places; diversification `2.48×`; `breaches` as `1 of 9`. Per frame: the nodes in `recomputed` and the edges into them take `--mark` and fade over 0.75 s — the same animation the ledger's underline uses, because it is the same fact. Under `prefers-reduced-motion` the last frame's set is a static mark until the next frame.

Staleness: for each stale symbol the client computes the downstream closure of `price[S]` from the served edges and applies the existing hatch and 0.38 opacity to exactly those nodes and nothing else. `feed:S` and `feed_health` for that symbol take `--over`. This is the current CSS's stated intent — "scoped by dependency, not by page" — done by dependency: today `main.stale` dims all of columns two and three, including `limit:aapl-cap`, which hangs off `exposure:AAPL` alone and is exactly right while CVX is quiet. The same closure is applied to the ledger's rows, which corrects that over-dim.

Two absences are drawn. Beside `covariance_ewma`, a dotted slot labelled `garch — implemented, not wired in`, with no edge into it and a link to §05. In the observers column, the alerts tracker with a dotted edge leaving it and ending at a terminal bar labelled `kill switch — wired to nothing`. The other two observers are the history ring (`500`) and the SSE broadcaster; the column is labelled outside the graph because that is where they are, and the alerts observer's edge from `breaches` is drawn from `/api/graph`'s `outside` list, not invented.

### `/ops` — the operations page

Two equal columns, `this host` and `peer`, in the ledger's key/value style; one column on a phone with this host first. The peer column is filled from the live origin (the demo's `/api/ops`, cross-origin, allowed because the demo engine publishes `Access-Control-Allow-Origin: *` on its JSON routes in demo mode only) and, from the demo origin, reads `the live host is behind a password — open live.ohcamel…/ops to see both`. A failed peer fetch renders `unreachable from this browser` in `--unknown`, never `down`.

Rows, each group ruled: **engine** — mode, up (`3d 4h 12m`), started_at, pid, container id, OCaml, build sha + built_at; **feed** — source, threshold, healthy / stale / never-seen counts, a feed-age strip (one dot per symbol on a 0..threshold axis; past the threshold in `--over`; never-seen as an open ring in `--unknown`; on the live host the dots are unlabelled counts, since names stay behind the password even from the owner's phone and there is no need for them here), Alpaca and FRED stats on live, `quiet by design: CVX` on demo; **stream** — EventSource state (`open` / `parked` / `reconnecting`), frames received in the last 60 s, last frame age, server frames_sent (`delivered to ≥ 1 subscriber; welcome frames excluded`), open subscribers, coalesce, keepalive; **book moving** — `history.appended` per minute; **process** — stabilizes, nodes_created, active observers, all Incremental's counters for the whole process and labelled so (*amended*); **alerts** — enabled, kill switch with tripped_by and tripped_at, halt, limits currently firing (the tracker's hysteresis state, so over the line and still-firing-below-it are distinguishable), sent / failed, sinks, trips_on, clear_below; **resources** — heap MB, top heap, minor / major collections, RSS; **reports** — static ready, garch computing k of 180 / done.

## Visual direction

A successor to the current page, not a repudiation: the same twelve tokens in both authored schemes, the same faces, the same three-state semantics, the same monospace-for-data rule, and the same single animation — now applied to nodes and edges as well as values, because they are the same fact. What is added is a document's discipline: a narrow reading measure for prose, wide or full-width figures interrupting it, rules rather than cards, captions that state the source, and one typographic distinction that did not exist before, between a number this process produced and a number it is quoting. NYT-graphics restraint, MoMA wall-label captions. Nothing glows, nothing pulses, no badges, no gradients (the semantic stale hatch stays), no green-on-black.

**Typography.** Unchanged stacks: `ui-sans-serif` for prose and labels, `ui-monospace` with tabular figures for every datum and nothing else. Prose at 15px/1.5 in a 68ch column (the current page is 14px; reading a column deserves one size up; the ledger stays at 14). Section heads are the README's headings verbatim, sentence case, 22px, weight 620, tracking −0.01em, preceded by a `.lbl` number. Node labels are `Node_name` strings and are therefore data: monospace 11px in `--ink-soft`, the value or count beneath in monospace 11px `--ink`. Figure captions 12px `--ink-soft`. Provenance tags in the `.lbl` treatment (10px, 0.14em, uppercase): `LIVE · THIS HOST`, `COMPUTED · AT STARTUP · 12:04:31Z`, `QUOTED · README · M2 PRO · 2026-08`, `SYNTHETIC`. Quoted numbers are set in `--ink-soft`, never `--ink`, so a laptop's microseconds cannot pass for this droplet's. No pull quotes, no drop caps, italics only where the README italicises.

**Palette.** The existing tokens — `ground`, `panel`, `ink`, `ink-soft`, `ink-faint`, `rule`, `over`, `over-wash`, `unknown`, `unknown-wash`, `live`, `mark` — in both schemes, unchanged. Two additions, each with a light and a dark value: `--second` (a slate, `#4a6d8c` / `#7fa3c2`) for the parametric estimator's series, and `--shade` (a 6% ink wash) for annotated spans. Assignments are fixed page-wide so a reader learns one legend: historical `--ink`, parametric `--second`, ewma `--mark`; hits, losses, breaches and the worst case `--over`; a hedge `--live`; lit nodes, lit edges and changed values `--mark`; `gated`, `unreachable from this browser`, `computing`, `warming up`, `does not apply`, `parked` in `--unknown` and its wash, because each is a cannot-evaluate and none may look like fine or like failure. Basel zones are words.

**Layout.** A grid with named lines: full → wide (1180px) → text (68ch). Figure 1 is full width; tables and charts wide; prose text. Figures are caption-above (title left, provenance right) with a rule above and below, no border. Sections are separated by one rule and space, never by a background change. Below 900px everything is one column as today; wide figures scroll inside their own `overflow-x: auto` container; the graph becomes a list of lit names below 700px; the header stops being sticky there. `/ops`: two columns of key/value rows, one on a phone, pulse strips under the engine group, the cannot-see paragraph last.

**Motion.** Exactly one animation, the existing 0.75 s fade of a `--mark` rule, applied to three things from the same frame: a changed ledger value's underline, a recomputed node's rule, and the edges into that node. Ages re-render once a second as text with no transition. Strips append a tick. The GARCH column fills row by row as data arrives, which is the only progress on the page. `prefers-reduced-motion` disables the fade; the mark still appears. No spinners, no counters ticking up, no scroll reveals, no bars animating to width.

**Charts.** All inline SVG built by hand in `web/charts.js`, strokes and fills on CSS variables so both schemes work without duplication, in the sparkline's idiom: shape and endpoints, no gridlines, no legend beyond a word at a line's end. Each form and the reason for it:

1. *The graph* — typographic nodes, hairline cubic edges between rank columns, observed dots, dotted absences. The project is about dependency structure and a node-link drawing is the only form that shows an edge; ranks by longest path because "downstream" is the argument; rows by symbol because a tick is a horizontal line.
2. *Scaling* — dot-and-line, categorical x (10, 100, 400), two series. Three sizes are not a continuum; two series that diverge is the claim, and the flat one is the argument.
3. *Bench, quoted* — the same form with a log y-axis in microseconds and the ratios printed at each x. 108× spans orders of magnitude; a log axis is the only honest linear reading. Soft ink, because it is a quotation.
4. *Attribution* — paired horizontal bars per name, signed, a hedge leftward, the standalone extent as a hairline behind. The claim is a gap between two shares per name; paired bars make the gap a distance; signed because a negative component is the "no stray abs" test made visible.
5. *Tenor buckets* — six fixed slots, signed bars in the occupied two, a zero rule for the total. The point is a parallel-shift total hiding two opposite bars; fixed slots show the empty tenors as empty.
6. *Exceedance strips* — a baseline one hairline per forecast day, hits as 1×6 px ticks. Clustering, regularity and absence are visible in a strip and invisible in a p-value; the comb is the Weibull test's reason to exist.
7. *Crisis timelines* — three small multiples, shared y, return bars, three −VaR lines, hits as dots for one estimator, annotated spans. The burst is a date; a shared axis makes 2008 and 2022 comparable; one estimator's dots at a time avoids overplotting.
8. *GARCH* — dot with ± sd whiskers at six log-spaced n, a true-value hairline, a window hairline. The whisker at 60 is the verdict; log x because the sample sizes roughly double.
9. *Stress* — signed horizontal P&L bars in suite order with breach names beside. Twelve signed numbers want comparing; suite order keeps the six standard scenarios first and each sector's selloff beside its squeeze.
10. *Frame-arrival strip* — 60 s axis, one tick per frame at arrival, trailing 20 s shaded. The smoke assertion is about spread in time; this is that assertion drawn.
11. *Pulse strips* (`/ops`) — Δ per poll as 1 px-gapped bars. A flat line of zeros is the alarm and needs no threshold.
12. *Feed-age dots* (`/ops`) — one dot per symbol on a 0..threshold axis. Staleness is age against a threshold and nothing else.
13. *Sparklines* ×4 — the existing function, moved verbatim.

Tables are HTML tables in the ledger's `td.k` / `td.v` idiom, never SVG. The bench table, the Basel column, the walk tables and the window facts get no chart: quoted numbers and four-row tables are read, not drawn.

## Signature moves

Each is derived from something true about the engine, and each is the successor of one of the three moves the current page makes.

**1. The drawing is the graph, taken from the graph.** Invariant 1 says every dependency is an edge. If that is true, the edges can be asked for — and Incremental keeps them: `Incremental.For_analyzer.traverse` over this graph's packed observers visits every necessary node with its `children` (the nodes it reads), and a label set at construction with `append_user_info_graphviz` comes back through `user_info`. `Graph.topology` names the nodes at the sites where they are already named for the `on_compute` hook, walks Incremental's table, contracts the unnamed plumbing (`Inc.all` folds, intermediate `map2`s) so edges run named-to-named, and assigns ranks by longest path. Nothing is hand-written that could drift from the wiring, and a test asserts the drawing's downstream closure of `price[AAPL]` equals the recomputation set `test_graph.ml` already pins. Successor to "the layout is the graph": from column order to the edges themselves.

**2. A tick is drawn on it.** Each SSE frame carries the names the `on_compute` hook recorded since the previous frame — the same hook the tests pin to exact sets — and exactly those nodes and their incoming edges take the mark. A print in AAPL lights `exposure:AAPL`, the aggregates, the estimators, five limits and `breaches`, and visibly does not light `covariance`, `covariance_ewma` or `limit:msft-cap`. The covariance pair stands still through forty ticks and marks once at the bar. Successor to "changed values are marked": the client used to infer change by diffing values; the engine now states what ran.

**3. Staleness follows the edges, not the column.** graph.ml's feed branch is deliberately disconnected from the risk graph, and a stale price compromises what is downstream of that price and nothing beside it. The page computes the downstream closure of `price[S]` from the served topology and dims exactly that — on the drawing and on the ledger — leaving `exposure:AAPL` and `limit:aapl-cap` at full authority while CVX is quiet. Successor to "the numbers lose authority when the feed does": the same rule, done by dependency, correcting the one place today's CSS over-dims.

**4. What isn't there is drawn.** Invariant 6 says the kill switch stays a bool wired to nothing, and `make garch` is the measurement behind not wiring GARCH in. Two strokes of ink on the drawing: a dotted slot beside `covariance_ewma` with no edge into it, and a dotted edge leaving the alerts observer that ends at a terminal bar. The repository argues by saying what a thing is not; the page does it without a sentence.

**5. Three provenances, and computed is checked against quoted.** The engine's rule is that unknown must never render as fine. The page's corollary is that a number this process did not produce must never look as if it had. Every figure carries one of three tags — `LIVE · THIS HOST`, `COMPUTED · AT STARTUP · time`, `QUOTED · source · hardware · date` — quoted figures sit in the soft ink, and synthetic carries its own word in every line. Where a table can be both computed and quoted (the battery, the crisis battery, the scaling rows, the GARCH study) the page holds the README's numbers in `web/quoted.json` and this process's, and prints one line: `agrees with the README's table to four decimals` or the cells that differ. The same comparison runs as a test on both CI legs. "Fixed seed, so the table is the same on any machine" stops being asserted in prose and starts being shown by the deployed host, and the PRNG-and-libm question the maps left open is answered by the deploy.

**6. Every report opens with the piece of the graph it interrogates.** `Stress.run` reads its results through the same nodes as the live book; the coverage battery scores the same estimators the estimator column holds; the attribution report is the `attribution` node's arrays, finally observed. So each section heads with the same renderer filtered to its nodes — the estimator stack for §04 and §06, `weights` + `covariance` → `attribution` for §02, the spine drawn twice for §07, the greeks branch for §03, the empty slot for §05 — and the reader never loses the thread from figure back to graph.

**7. The smoke suite runs in your browser.** `smoke.sh` says the health route returning 200 proves almost nothing and that two assertions carry the weight: the counter advances across two seconds, and distinct frames spread across twenty. The engine cannot report the last smoke run (nothing persists), so the page re-evaluates both continuously on the frames it already receives and draws the second as a frame-arrival strip — with `history.appended` beside the counter as the signal forks cannot inflate, and the build sha with its uptime as the proof of deploy the suite itself lacked.

### Where the topology comes from

`Graph.create` already names every derived node at its `note Node_name.x` site. This design names the node object too: a helper `named name node` calls `Inc.append_user_info_graphviz node ~label:[name] ~attrs:String.Map.empty` and returns the node; `make_var` gains `~name` and labels `Inc.Var.watch v` with the input cell's name from a new `Node_name.Input` (`price[AAPL]`, `qty[AAPL]`, `returns[AAPL]`, `last_tick[AAPL]`, `cash`, `equity_history`, `factor_returns`, `contracts[ID]`, `implied_vol[ID]`, `rate`, `valuation_days`, `now`). `Graph.topology t` then packs this graph's 27 observers (`Inc.pack (Inc.Observer.observing o)`), calls `Incremental.For_analyzer.traverse` with an `add_node` that records id, kind, cutoff, children and the label, contracts every unlabelled node by walking through it to its labelled ancestors, assigns ranks by longest path from the Vars, and classifies families from the name prefix. It costs nothing on the tick path and is memoised once in `Server.create`. Because it traverses from this graph's observers, a fork or a probe alive in the same process does not leak into it.

What guards it: a test that the topology's names equal the set the `on_compute` hook records after one full stabilize; that the downstream closure of `{price[AAPL], last_tick[AAPL]}` equals `test_graph.ml`'s pinned `apply_tick` set and of `returns[MSFT]` the pinned `push_return` set; that `covariance` and `covariance_ewma` are downstream of no price cell; that `limit:aapl-cap`'s upstream is exactly `exposure:AAPL`; and that no risk node is downstream of `now`. The three edges graph.ml's header says are worth staring at become assertions.

### The recompute log, and where it drains

`lib/recompute_log.ml`: `create`, `note : t -> string -> unit` (a `Hashtbl.incr` into a per-frame table and a lifetime table; it cannot raise, which matters because it runs inside node bodies), `drain : t -> (string * int) list`, `distinct`, `total`, `hottest ~n`. `run_demo` and `run_live` create the served graph with `~on_compute:(Recompute_log.note log)` — the demo graph is built with no hook today — and pass the log to `Server.create`. `run_broadcaster` drains it after `Graph.snapshot` returns and before serializing, and passes the list into `render ?recomputed`. It is never drained in `render` itself, because `render` is also called by `/api/snapshot` and by every new subscriber's welcome frame, either of which would steal the stream's set; `/api/snapshot` carries `null`. A render-time stabilize that changes something fills the next Ivar and produces a follow-up frame whose set is tiny or empty; it is emitted honestly as `recomputed: []` and tested as such. `Graph.fork` does not inherit the hook, so `/api/stress` never touches it.

### Values by node

The drawing's per-node values are not a client-side table mapping node names to snapshot fields — that would be a second description of the encoder, one refactor from silently mislabelling a node. `json_of_snapshot` emits `by_node` itself, next to the fields it already reads, and `Node_name.unit_of` in graph.ml gives each name its unit for the topology. A test asserts that every topology node whose unit is scalar has a `by_node` key on a warmed-up snapshot.

### Startup

Before `Server.start`, in both `run_demo` and `run_live`, in this order: the scaling probe (10 / 100 / 400 names, 50 ticks; 0.31 s for all of synthetic mode on the M-series laptop; budget 1.5 s on the s-2vcpu droplet) — run first, before the served graph is created, so its thousands of node creations land before the first tick and the smoke suite's "counter advances" read is not the probe's tail; then `Graph.create` with the recompute log; then the synthetic battery (~50 ms), the crisis battery from the embedded CSVs (~50 ms, three throwaway graphs destroyed in `Exn.protect`), the options walk (~20 ms). In `run_live` all of this precedes the awaited Alpaca backfill, which already spends the 20 s healthcheck start period. The reports are encoded once and held as strings.

After `Server.start` resolves: the GARCH study on a second domain. `Garch11.fit` is pure OCaml over float arrays — Owl appears in `vol_estimators.ml` only inside the EWMA covariance — and `Domain.spawn` works in this switch (verified 2026-09-02), so the study runs in parallel on the droplet's second vCPU and never holds the Async scheduler. The domain touches nothing of Async's: it takes its own `Random.State`, calls `Garch_study.run` with a `progress` callback that stores the fit count in an `Atomic.t`, and its result is collected by `Domain.join` from a one-second `Clock.every` poll on the main domain once the counter reaches 180, then encoded once and cached. The route reports `computing` with `done` and `of` until then. What this costs is one core for roughly five to fifteen seconds after each start and the stop-the-world minor collections a second domain adds, both measured on the droplet at the first deploy and recorded in `status.md`. If domains misbehave under Async there, the fallback is the chunked loop the panel first proposed — one fit per scheduler turn, delayed past the smoke window — and it is not built unless needed. Nothing is ever computed inside a request handler except `/api/stress`'s twelve forks, as today; `/api/graph` is memoised; `/api/ops` is `Gc.quick_stat` plus field reads.

## What this design is afraid of

**That the numbers do not reproduce on the droplet.** The README's synthetic and crisis verdicts were produced on macOS/arm64; the container is Debian/glibc/amd64, and one flipped borderline exceedance changes a p-value and possibly a verdict. The pinned-value tests land in the extraction phase and run on the ubuntu leg before the page ships, so the answer is known before it is public. If a cell differs, the page prints it — `computed on this host (linux, amd64): differs from the README's table (macOS, arm64) in N cells: …` — and the README gets a footnote naming the machine rather than a silent edit.

**That the drawing is a hairball.** Fifty-three nodes and about 150 edges in 360 px. Before `graph.js` is written, the six-name topology is prototyped as a static SVG from the real `/api/graph` output and looked at. If it does not read, the fallback is family bands with per-name rows only for the ticking name, and the caption says so. A diagram that has become decoration is exactly what the interviewer lens watches for.

**That GARCH stalls the stream after a deploy.** Answered by running it on a second domain, which parallelises rather than time-slices; measured on the droplet at the first deploy. Never in a request handler, never before the socket binds, never on a systhread (those time-slice pure compute). The fallback if domains misbehave under Async is the chunked loop, delayed past the smoke window.

**That the stream's set is stolen.** Drained only in the broadcaster after `Graph.snapshot`; `null` on `/api/snapshot`; tested.

**That a report graph leaks.** Every probe, crisis and options graph is destroyed in `Exn.protect ~finally`; a test asserts the served graph's log is untouched after a probe. The stabilize is process-wide and an undestroyed graph recomputes on every tick forever.

**That the live wire changes under the owner.** Passing `?alerts` in serve mode makes the live header report the armed switch it has always had, and wiring the hook into the demo graph changes nothing a viewer could see except the new field. Both are stated here so neither is a surprise.

**That the page's prose drifts from the README's.** The section headings are the README's by rule, the prose is short and cut from it, and every number in it that appears in a figure is bound to the figure's data. The duty to change both when the argument changes is stated, not automated: a heading test would need the README in the test binary, which is a hand-typed list guarding a hand-typed list.

**That a deploy keeps the old container and nobody notices.** `--expect-sha` and `uptime_s < 300` on every deploy.

**That someone breaks the delimiter.** A CI grep, and the failure is a compile error with a filename, not a truncated page.
