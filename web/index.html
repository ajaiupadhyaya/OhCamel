01Why it isn't a loop

Most real-time risk systems poll. A timer fires, the whole book is recomputed and rendered, and the process sleeps. The number on screen is then as old as the timer's last tick rather than the market's, and a print in one name pays for a covariance matrix that no price could have changed, because covariance is computed from a return window a mid-session print does not touch.

Here risk is a dependency graph. A tick sets one input cell and Incremental recomputes exactly what is downstream of it. Figure 1 is that graph, and every frame lights what ran. The rest of the graph is never visited, which is different from being recomputed and found unchanged.

Waiting for the first frames.

The node count is flat and the wall clock is not. A tick reaches about twenty-six nodes at every book size, but some of those nodes are O(n), and the Euler decomposition is O(n²). What incrementality removes is the O(n²·w) covariance rebuild, the most expensive thing in the engine. That is why the gap widens from 2.7× to 108× as the book grows instead of staying constant.

02Where the risk is

A portfolio VaR is a fact about the book, not an instruction. Sorting positions by size answers a different question, because money and risk are not the same distribution. Portfolio volatility is homogeneous of degree one in the weights, so Euler's theorem splits it exactly. Each name's contribution sums with the others to the whole, over any partition of the book, which is what makes a limit on one name's share of VaR well posed.

A contribution can be negative, because a position that moves against the book reduces its volatility, so a hedge uses none of its risk limit however large it is. test_graph.ml asserts that directly. A stray absolute value anywhere in the chain would breach a risk limit for the act of hedging.

04Is the number any good

“95% VaR” is a testable claim. The loss should exceed it on about 5% of days, and those days should be scattered rather than bunched. Three series, three estimators and four tests. Kupiec asks whether there are the right number of exceptions. Christoffersen asks whether they arrive back to back. Conditional coverage joins the two. The duration test asks whether the waiting times between exceptions are memoryless, which catches clustering that is not on adjacent days. Every forecast uses a window that ends the day before the day it scores.

—

A rejection here is the suite working. On jumps, the parametric row has exactly 47 exceptions against 47 expected and passes three tests. The duration test rejects it, because a −8% loss every twentieth day is a metronome and not a market. Its strip reads as a comb.

The live host's own track record is not here. The engine does not persist forecasts, so there is no coverage test of the live VaR. That needs persistence, which is a separate argument.

05The estimator that is implemented and deliberately not used

GARCH(1,1) adds what EWMA has no notion of: a long-run level to revert to. Its persistence, α + β, says how much of a volatility shock survives each period, and that number is the whole reason to prefer it. It is implemented and tested in lib/vol_estimators.ml, and it is not wired into the graph. This process simulates a known GARCH with persistence 0.98 and a 34-day half-life, fits it back thirty times at each sample size, and draws where the fits land.

At this engine's 60-observation window, a fit carries almost no information about persistence.

06The same battery, real crises

Synthetic tails are drawn from the distribution the author had in mind, and real ones are not. So the same battery runs over three real windows (the global financial crisis, COVID and the 2022 rate shock), using adjusted closes committed to the repository and compiled into this binary. Today's six-name book is held at constant weights: what today's book would have done through each window.

—

— Survival is not reassurance. On COVID the parametric row takes ten exceptions in a single 21-session window with a joint p of 0.073, which is no rejection. The duration test catches it. The five exceptions around Lehman are caught only by the burst count, which is not a test and is labelled as such. Three instruments have three different blind spots, and reading any one alone is how a model breaching ten times in a month gets a passing grade.

07What would break it

VaR and limits can only speak about moves that are already in the return window, and a scenario asks the other question. There is no scenario arithmetic in this repository. Graph.fork copies the engine, the shocks are written into the fork's input cells, and the answer is read by the same nodes that produce the live one. The scenario is the engine fed different inputs, not a model of it.

08What's verified

—

Every deploy runs a smoke suite, and a failure fails the deploy. The assertion worth naming is not the health route returning 200, which proves almost nothing. It is that nodes_recomputed advances between two reads two seconds apart, and that the stream delivers distinct frames spread across twenty seconds rather than piled up at the end. A frozen graph serves valid JSON forever.

—

The tests are hermetic: no network, no credentials, and nothing that waits on the wall clock. Seven are worth knowing by name. Euler residual holds the decomposition to its identity. Hedge checks that a risk-reducing position does not breach a risk limit. Lookahead rebuilds every rolling window independently, so a backtest cannot see the day it forecasts. Isolation compares the live snapshot field for field after the scenario suite. Regime break checks that EWMA reads higher volatility after a shift. Delta-hedged checks that a delta-flat book still carries gamma and vega. Two clocks checks that the staleness clock reprices no option.

Price, Qty and Notional are abstract and mutually incompatible, so price + qty is a compile error rather than a plausible-looking number. Every formula is cross-referenced to the function that evaluates it in docs/quant_notes.md.

09What this is not

There is no order routing and no execution. Nothing here places, cancels or simulates a trade, and the kill switch sets a flag that is wired to nothing. There is no persistence: state lives in the running process, and a restart rebuilds the book from its file and the feed. It is not a research platform either. The backtests validate the risk model, not a trading idea, and nothing is optimised.

This page does not show the last smoke run's result, because nothing persists. It shows no uptime percentage, no CPU share and no certificate expiry, which the engine cannot observe. It shows no microsecond timings from this host and no options Greeks on either deployed book. It never shows the live book, which stays behind a password. And there is no market calendar: outside market hours the live host reads parked and says nothing more.

It is a risk and limits engine, and it stops where a risk and limits engine should stop.
